# Leantime Documentation

Source of [docs.leantime.io](https://docs.leantime.io), built with [Astro Starlight](https://starlight.astro.build/).

## Editing a page

**Read [CONTRIBUTING.md](CONTRIBUTING.md) first.** It has the writing rules, the page structure, when to use which component, and the words we use, so every page reads the same way.

Pages are Markdown files in [`src/content/docs/`](src/content/docs/). The file path is the URL:
`src/content/docs/installation/docker.md` → `https://docs.leantime.io/installation/docker/`.

Every page starts with front matter:

```markdown
---
title: Docker based Installation
description: One or two sentences for search results and link previews (about 150 characters).
---

Page content starts here. Don't repeat the title as a "# " heading; Starlight renders it.
```

- Link to other pages by their URL: `[Docker](/installation/docker/)`, `[a section](/installation/docker/#volumes)`.
- Pages built from the old docsify site are regenerated by `scripts/docsify-to-starlight.py` until the migration merges. Hand-built pages that use components (the home page, the Docker guide) live in `scripts/overrides/` so a re-run keeps them; edit them there.
- Images go in `public/_images/` and are linked as `/_images/...`.
- The menu lists pages by name in [`astro.config.mjs`](astro.config.mjs). Add a new `using-leantime/` page to a group in `USE_LEANTIME_GROUPS` (the build stops and names any page that isn't placed), a `getting-started/` page to `START_HERE` (or `WORK_TYPES` for the examples), and other pages to `sidebar`. Add a `knowledge-base/` page to `CONCEPT_PAGES`. Only `api/classes/` pages appear automatically.

## Running it locally

Requires Node.js 22.23.4 or later.

```bash
npm ci
npm run dev       # live preview at http://localhost:4321
npm run build     # checks headings, then builds dist/; fails on heading problems or broken internal links
npm run preview   # serve the production build
```

## Publishing

Every pull request is built by the **Build docs** workflow, which also checks all internal links.

docs.leantime.io is served from Coolify. Merging to `master` doesn't publish anything: redeploy the docs resource in Coolify. It builds the site with `npm ci && npm run build` (Node.js 22.23.4 or later) and serves the `dist/` folder.

The **🚀 Deploy Docs** workflow uploads over FTP, which no longer reaches docs.leantime.io (Cloudflare in front of it doesn't pass FTP). Don't use it.

## Search engines and AI tools

Each page is static HTML with its own title, description, canonical URL and structured data (schema.org `TechArticle` and `BreadcrumbList` on every page except the home page, plus site-wide `Organization`, `WebSite` and `SoftwareApplication` in `astro.config.mjs` and `src/routeData.ts`). The build also writes `sitemap-index.xml`, `robots.txt` and `llms.txt`, `llms-full.txt` and `llms-small.txt` for AI assistants, and a plain Markdown copy of each page (`/path.md`, not for the home page or drafts).

Old docsify links (`/#/installation/docker`, `?id=section`) are redirected in the browser.
